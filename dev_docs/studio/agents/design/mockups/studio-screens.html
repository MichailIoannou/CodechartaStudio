How it fits together

Journeys

J1First start

  1. Project home → New project…
  2. Name it, Add folder… picks the repository
  3. Analyse on the folder; the analyses indicator shows progress
  4. Map opens; the nav bar reads billing ▾ | billing-api @ a1b2c3d ▾ | ⎇ main, and the History tab appears

J2Open a cc.json

  1. Project switcher → Open cc.json… (Ctrl+O)
  2. The dialog says which project it goes into, labels it "analysis time unknown", and offers to bind it to the commit its name points to
  3. The map shows it; the selector reads "Downloads · imported"

J3Everyday start

  1. The last project and analysis reopen
  2. If the checkout moved on, the selector shows "stale by N" and the notice offers Analyse
  3. Nothing runs by itself

J4Another commit, from the map

  1. Map selector ▾ → Show commit…
  2. Type a branch, tag or hash; entries say if they're analysed
  3. Pick → the map switches, or shows the nearest analysis with "stale by N" and Analyse
  4. Show current checkout goes back

J5Another commit, from History

  1. History tab, or click the branch chip
  2. Browsing commits only fills the details pane, so arrow keys stay fast
  3. Show in map (or Enter) → metric view with that commit
  4. Analyse this commit queues it without leaving History

J6Everyday git

  1. History → Changes: stage, write the message, Commit
  2. Fetch / Pull / Push next to the branch
  3. The branch chip updates; a map that follows the checkout may now say "stale by N"

J7Compare

  1. Map: hover Metric → Compare opens the compare dialog. History: select two commits → Compare, or a branch → Compare with 'main'
  2. Missing analyses: Analyse missing or Use nearest
  3. The selector's place shows base 9f8e7d6 ⇄ head a1b2c3d; the explorer gets a Changes list
  4. Explore or Leave compare returns to one map

J8Switch project

  1. Project switcher ▾ → another project
  2. Its last analysis loads; the selector, branch chip and History follow its active folder

How to read the commit list

A commit. The line leads to its parent (older commit). HEAD: the commit your folder has checked out. Your uncommitted changes, on top of HEAD. A merge: two lines of development join at this commit. Each colour is one line. mainThe branch you're on. Outlined: other local branch. Grey : branch on the remote. : tag. analysedCodeCharta has an analysis of this commit. "in map": it's the one the map shows. Also: queued, 42 %, failed.

The rows show a real history: "Release 2.4.0" on main (orange line) is merged into the feature branch (blue line) by the merge row, and both lines start from "Start the invoice module". The pills in the Fix row are cut by design to show the truncation rule: rounded ends, "…" inside, full name on hover.

Where the design departs from the plans

Decisions the implementer will follow

03 · 05

One map selector for folders, commit and snapshot status, including "Show commit…".

Plans 03 and 05 each added a control naming the shown snapshot. Neither let you pick a commit from the map screen.

03 · 04 · 05

An explicit active folder, remembered per project.

History's "Repository" and the map selector's ● marker set the same thing.

05

Browsing commits in History does not change the map; "Show in map" does.

Loading a large map on every arrow key would be slow.

04

Toolbar shows repository, branch and sync; filters live in the panes they filter; words instead of letters and icons; uncommitted changes drawn in the graph.

From your review.

04

Git failures show inside History with Details; branch switch confirms only with uncommitted changes.

06

No separate Compare button; the existing Compare tab opens the compare dialog. The commit picker is shared with the map selector.

05 · 01 · 02

Stale notice over map views only; confirm before moving the store folder; theme toggle names its destination.

Your call

Open questions, with the default applied

1ProjectsOne map selector for folders and snapshot status?Default: yes, as shown above.
2ProjectsShould the user choose the active folder explicitly?Default: yes. The alternative is always using the first shown folder.
3ProjectsHow many folders may be shown side by side?Default: no limit.
4HistoryConfirm every branch switch?Default: only with uncommitted changes.
5HistoryWhere do git failures show?Default: in History with Details; successes as toasts.
6SnapshotsDoes selecting a commit change the map?Default: no, only "Show in map" or "Show commit…".
7SnapshotsStale notice in History too?Default: no; the details pane says it per commit.
8CompareA Compare button in the nav bar?Default: no; the existing Compare tab opens the dialog.
9Themes"IntelliJ Light" or "Rider Light"?Default: "IntelliJ Light", as plan 02 has it.
10ThemesBorder on explorer and inspector edges?Default: yes; their shadow disappears on a dark map.
11Desktop toolsConfirm before moving the store folder?Default: yes, because the app restarts.
