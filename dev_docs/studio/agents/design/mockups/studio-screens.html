How the CodeCharta screen changes in the desktop app. This revision follows your decision: a project groups folders, you work in one folder at a time, and one status element shows branch, map and running work.

Workspace status · every state

The icon shows the activity, the background shows progress

Every state has the same width: the element is fixed per window size, and activity only changes how many characters fit before "…". The icon slot is fixed too, so the spinner and arrows never push the text. It is a dropdown trigger shaped like today's map selector. The branch icon turns into the activity, and the background fills with progress reported by the core. When the core reports no percentage, a band sweeps across instead (static if you've asked your system for reduced motion).

Git sync · after Zed

One button that does what the branch needs

The main part runs the action that fits the branch's state. The caret lists the others: Fetch, Fetch and remove deleted branches, Pull, Push, Publish, Force push (with lease)…, Set upstream…. While it runs, it reads "Pulling…", is disabled, and its caret becomes Cancel. It doesn't animate: the status element at the top already shows the progress. The same button appears in History, in the status element and on the project overview. Commit stays in History's Changes tab.

How it fits together

Journeys

J1First start

  1. The overview opens in its "no project" state: New project…, Open cc.json…, Show sample maps
  2. Name the project, Add folder… for the repository (forks and helper folders can be added later)
  3. The overview shows the working folder with "No analysis yet" → Analyse current checkout
  4. The status element spins and fills; when it's done, it flashes green and the map opens

J2Open a cc.json

  1. Project menu → Open cc.json… (Ctrl+O)
  2. The dialog says which project and folder it goes into, and labels it "analysis time unknown"
  3. Open: that folder becomes the working folder; the status reads "imported"

J3Everyday start

  1. The last project, working folder and analysis reopen
  2. If the checkout moved on, the status says "stale by N" and the notice offers Analyse
  3. Nothing runs by itself

J4Switch folder or project

  1. Project menu → choose another folder of this project (for example the fork)
  2. Or open another project under "Other projects" and choose one of its folders
  3. Its last analysis loads; the status element, History and the overview follow

J5Another commit, from the map

  1. Status ▾ → Show commit…; type a branch, tag or hash
  2. Analysed → the map switches. Not analysed → the nearest analysis shows with "stale by N" and Analyse
  3. Show current checkout goes back

J6Another commit, from History

  1. History tab, or Status ▾ → Open History
  2. Browsing commits only fills the details pane
  3. Show in map (or Enter) switches the map; Analyse this commit queues it, and progress shows on the status element

J7Everyday git

  1. The sync button offers Pull, Push, Publish or Fetch to match the branch
  2. While it runs, the status icon becomes the arrow and the background fills
  3. To commit: History → Changes: stage files, write the message, Commit

J8Compare

  1. Hover Metric → Compare, or in History select two commits → Compare
  2. Missing analyses: Analyse missing or Use nearest
  3. The comparison chip sits next to the status icon; the explorer gets Changes

J9Check on a project

  1. Project menu → Overview
  2. See the git state, analyses, recent commits and folders
  3. Show map returns

How to read the commit list

A commit. The line leads to its parent (older commit). HEAD: the commit your folder has checked out. Your uncommitted changes, on top of HEAD. A merge: two lines of development join at this commit. Each colour is one line. mainThe branch you're on. Outlined: other local branch. Grey : branch on the remote. : tag. analysedCodeCharta has an analysis of this commit. "in map": it's the one the map shows. Also: queued, 42 %, failed.

The rows show a real history: "Release 2.4.0" on main (orange line) is merged into the feature branch (blue line) by the merge row, and both lines start from "Start the invoice module". Here a pull is running. Only the status element at the top animates; the sync button just says "Pulling…" and offers Cancel, and the commit list shows "42 %" as plain text.

Where the design departs from the plans

Decisions the implementer will follow

OD1 · 03

One working folder at a time; the project menu chooses project and folder.

Plan 03's multi-folder selector and side-by-side display are dropped. The store format changes now (03-M1).

OD2 · 04 05

One workspace status element with the activity icon and a progress fill.

Replaces the snapshot chip, the branch chip and the analyses indicator.

OD3 · 04

One contextual sync button, after Zed.

Replaces separate Fetch, Pull and Push buttons.

OD4 · 03

Project overview page, reachable any time.

Replaces the project home that only showed when no map was loaded.

05

Browsing commits in History does not change the map; "Show in map" and "Show commit…" do.

04

Filters live in the pane they filter; words instead of letters and icons; uncommitted changes drawn in the graph; failures shown inside History.

06

No separate Compare button; the existing Compare tab opens the compare dialog.
