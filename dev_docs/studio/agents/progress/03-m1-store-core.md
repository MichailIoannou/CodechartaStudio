`store.json` with migrations, a per-process lock, the active-project session, and `store.status` with a

## Notes

Environment (2026-11-18): Arch Linux x86_64, rustc/cargo 1.95.0, node 26.13.0, npm 12.2.2. Every task
also ran `cargo clippy --all-targets --all-features --target x86_64-pc-windows-gnu -- -D warnings`, which
compiles the `cfg(windows)` code; nothing ran on Windows.

### 1. Paths and ids
- Newtypes `ProjectId`, `FolderId`, `SnapshotId` live in a new `codecharta-core-api/src/ids.rs` (shared by
  the later `projects` and `snapshots` types), generated by one `store_id!` macro: `try_from`/`into`
  `String`, `^[a-z0-9-]{1,96}$`, `as_str`, `Display`. The other newtypes of section 3 (`CommitHash`,
  `FullCommit`, `PickToken`, `Label`, `ProjectName`, `Description`) arrive with their first user (M2/M3).
  None of them is in the TypeScript contract yet, because no method names them.
- `ids.rs` (core): `new_project_id`, `new_folder_id` from `getrandom::fill` (8 bytes, hex). `getrandom`
  0.4.3 was already in `Cargo.lock` through `tempfile`, so no new package. `new_token` and
  `imported_snapshot_id` arrive with M2/M3.
- `store/paths.rs`: `StorePaths` (`store_file`, `session_file`, `lock_file`, `projects_dir`, `project_dir`,
  `project_file`, `folder_snapshots_dir`, `snapshot_dir`, `map_file`), file-name constants and
  `STAGING_FOLDER_PREFIX`. The inside-root check is lexical (the path must be the root plus only normal
  components), which is what an id-built path can get wrong; it does not canonicalise, since most of these
  paths do not exist yet. `confine_to_folder` refuses empty, absolute and `..` paths (`BAD_REQUEST`), a
  missing file is `NOT_FOUND`, a canonical path outside the canonical folder is `NOT_ALLOWED`. The
  symlink test is `cfg(unix)`; no `dunce`: both sides are canonicalised the same way, so a `\\?\` prefix
  on Windows is on both (not verified on Windows).
